# VKR AI — формирование и управление темами ВКР

Веб-система для направления **09.03.01 «Информатика и вычислительная техника»**. Преподаватели хранятся в постоянной базе, администратор выбирает нужных руководителей и количество тем, а система генерирует новый набор тем, проверяет похожесть и публикует утверждённый результат.

## Основной сценарий

1. **Новая генерация** — выбрать преподавателей, количество тем (до 10+ на преподавателя при необходимости) и необязательный фокус.
2. **Темы ВКР** — проверить результаты, отредактировать/перегенерировать, утвердить или отклонить темы.
3. **Публикация** — выгрузить утверждённые темы в XLSX или Google Sheets.
4. **Настройки** — Mistral API, Google Sheets и параметры генерации.

**База преподавателей** открывается из «Новой генерации», а **История наборов** — из «Темы ВКР».

## Что реализовано

- постоянная база преподавателей с сортировкой: профессор → доцент → преподаватель → без должности, затем по ФИО;
- одна или две кафедры (`САПРиПК` и/или `ЭВМиС`), контакты, научные области, ORCID, Scopus Author ID;
- прошлые одобренные темы ВКР преподавателя как основной персональный контекст для AI;
- импорт прошлых ВКР из XLSX с предпросмотром, сопоставлением преподавателей и дедупликацией;
- JSON backup/restore базы преподавателей;
- генерация **новых** практических тем через прямой Mistral API;
- массовая генерация до ~100 тем за одну пользовательскую операцию: 5–10 тем на преподавателя;
- очередь коротких AI-запросов: один преподаватель и до 10 тем на один Mistral-запрос;
- реальный прогресс генерации в интерфейсе: создано X из N тем и номер текущего преподавателя;
- основная AI-генерация работает строго через Mistral: при 429, таймауте или неполном ответе набор не подменяется локальными темами;
- отдельная кнопка **«Демо без ИИ»** запускает локальный демонстрационный банк явно и независимо от Mistral;
- каждая тема хранит происхождение (`Mistral AI` или `Демо без ИИ`) и модель генерации;
- проверка похожести отдельно по прошлым темам преподавателя и по всей исторической базе + текущему набору;
- точный текстовый дубликат выделяется отдельно; обычная похожесть использует локальные multilingual embeddings + лексический fallback, независимо от лимитов Mistral;
- локальная similarity-модель работает на CPU через FastEmbed/ONNX; при её недоступности включается отдельный lexical fallback со своими порогами;
- история наборов, удаление одного набора и полная очистка истории; после полной очистки следующий набор снова получает номер `#1`;
- одинаковая сортировка результатов в интерфейсе, XLSX и Google Sheets;
- Google Sheets через сервисный аккаунт и существующую таблицу.



## V34 — Compact AI response

V34 исправляет таймаут `Mistral (ministral-8b-2512) ... structured-ответ за 40 секунд`. Основная и AI-repair генерация просят Mistral вернуть только `teacher_id + titles[]`; rationale/keywords больше не входят в AI structured-output. Это резко сокращает число output tokens и сложность JSON Schema, а Quality Gate по-прежнему выполняется локально. Для 5 итоговых тем 7 AI-кандидатов требуют около 490 output tokens вместо прежних 1100+; основной 8B-вызов получает до 55 секунд. Скрытого local fallback нет.

## V33 — Technical Quality Gate

В этой версии качество тем контролируется после ответа LLM, а не только промптом:

- названия строятся как понятные **проекты по 09.03.01**: тип программного продукта → прикладная задача → 1–2 ключевые функции;
- чрезмерно узкие/экзотические сюжеты без опоры на профиль преподавателя запрещены промптом;
- rationale формируется как **«Техническая цель → Реализация → Проверка»**;
- соответствие `research_areas` дополнительно проверяется локальными multilingual embeddings, если модель уже загружена similarity-модулем;
- отдельно считается похожесть с прошлыми темами преподавателя, со всей базой и **внутри текущего batch**;
- внутри одного набора используется более чувствительный порог, чтобы похожие варианты уходили на AI-repair;
- слабая/чужая тема больше не используется только ради красивого `5/5`: после repair набор может содержать меньше запрошенного количества, но без заведомо плохого кандидата;
- UI показывает Quality Gate: `✓ Прошла`, `⚠ Проверить`, `✕ Блокирует`, причины и ближайшую тему текущего набора;
- XLSX/Google Sheets дополнительно выгружают внутрибатчевую похожесть и техническую цель.

## Mistral API

В v23 **Mistral — единственный внешний AI-провайдер**. Прежние AI-провайдеры удалены из интерфейса, настроек, Docker-конфигурации и runtime-логики.

По умолчанию:

```text
Модель генерации:  ministral-8b-2512
Модель embeddings: mistral-embed
```

Mistral Chat Completions используется со строгим structured output (`json_schema`), поэтому backend ожидает формализованный ответ `teacher_id → topics[]`. Все обращения к Mistral (проверка моделей, генерация и embeddings) проходят через общую последовательную очередь с интервалом не менее 1,25 секунды. При временном `429` выполняются автоматические повторы через `2 → 4 → 8` секунд с учётом заголовка `Retry-After`.

Если Mistral API Key не настроен, основная кнопка **AI-генерации блокируется**. Система больше не подменяет ответ LLM готовыми темами. Для демонстрации интерфейса без внешнего API доступна отдельная кнопка **«Демо без ИИ»**; такие темы явно помечаются как локальные. Прошлые ВКР используются как контекст и не выдаются за новую тему.

### Настройка ключа

В Mistral Studio создайте API key и вставьте его локально в:

**Настройки → ИИ → Mistral API Key**

Не добавляйте ключ в Git и не отправляйте его в чат.

## Массовая пакетная генерация

Одна кнопка может запустить генерацию примерно **100 тем**, например:

```text
10 преподавателей × 10 тем = 100 тем
20 преподавателей × 5 тем  = 100 тем
```

Начиная с v28 backend обрабатывает **каждого преподавателя отдельным коротким AI-запросом**. Это уменьшает объём structured-output ответа, снижает latency и исключает смешивание профилей преподавателей.

Для массовой генерации используется маршрут:

```text
ministral-8b-2512
        ↓ при 429 / 5xx / таймауте
ministral-3b-2512
```

Обе модели — Mistral AI. Локальный банк в основной генерации не используется. Для каждого преподавателя создаётся до 10 тем за один запрос; если нужно больше, запрос делится на несколько частей. После каждого преподавателя frontend получает NDJSON-событие и показывает реальный прогресс `создано X / N`.

Если обе Mistral-модели недоступны, AI-операция завершается ошибкой и набор откатывается. Локальный demo-режим запускается только отдельной кнопкой **«Демо без ИИ»**.

## Проверка похожести

Для каждой темы считаются два независимых показателя:

- **Прошлые темы** — только история ВКР этого преподавателя;
- **По всей базе** — исторические ВКР всех преподавателей + другие темы текущего набора.

Точное нормализованное совпадение — `100 · точный дубликат`. Для остальных пар система сочетает содержательную лексику и embedding-сигнал. Если Mistral Embeddings недоступны, используется локальный лексический расчёт без остановки генерации.

## Google Sheets

Для текущего надёжного сценария:

1. создать отдельную Google-таблицу;
2. дать сервисному аккаунту права **Редактор**;
3. вставить JSON сервисного аккаунта и ID таблицы в **Настройки → Google Sheets**.

При публикации приложение записывает утверждённые темы в первый лист в диапазон `A:E`:

```text
Преподаватель | Тема | Источник | ФИО студента | Контакты преподавателя
```

Перед записью `A:E` очищаются, поэтому используйте отдельную таблицу для проекта.

## Запуск через Docker

```bash
cp .env.example .env
docker compose up --build
```

Открыть:

- сайт: `http://localhost:3000`
- Swagger: `http://localhost:8000/docs`

Для обновления существующей установки не удаляйте volume PostgreSQL. Команда `docker compose down -v` удалит базу.

## Импорт прошлых ВКР

Откройте **Новая генерация → База преподавателей → Импортировать прошлые ВКР** и выберите `.xlsx`.

Система определяет листы и колонки, сопоставляет руководителей, показывает предпросмотр и после подтверждения добавляет уникальные темы в историю преподавателей.

## Тесты

```bash
cd backend
pytest -q
```

Backend-набор содержит проверки Mistral structured output, embeddings, общей последовательной очереди, backoff при 429, пакетной генерации, сортировки, импорта, истории, similarity, экспорта и интеграционного workflow.

## Free-тариф Mistral: рекомендуемая настройка

Для текущих бесплатных лимитов используйте:

```env
MISTRAL_CHAT_MODEL=ministral-8b-2512
MISTRAL_EMBEDDING_MODEL=mistral-embed
```

Кнопка «Проверить Mistral» делает только лёгкий запрос списка моделей и не расходует chat/completions. Начиная с v30 массовая генерация по умолчанию использует одну модель (`ministral-8b-2512`) на весь batch, чтобы качество не менялось от преподавателя к преподавателю. Автоматический переход на 3B выключен; его можно явно разрешить через `MISTRAL_ALLOW_SMALL_FALLBACK=true`. Локальный банк автоматически не подставляется.

## v26: защита от долгого ожидания Mistral

В v28 тяжёлые пакеты заменены короткими запросами по одному преподавателю. Основная Mistral-модель получает до 20 секунд, резервная — до 15 секунд. Интерфейс получает heartbeat каждые 5 секунд. Локальный fallback в AI-режиме не используется; семантическая проверка при необходимости переключается на лексическое сравнение.

## v29: автоматический AI-добор

Если часть ответа Mistral отфильтрована как слишком общая или слишком похожая на прошлые темы, система не падает на `4/5`: она делает адресный дополнительный Mistral-запрос только на недостающие темы. Локальный банк в AI-режиме не используется.


## v30 — quality gate профиля и дублей

Главное изменение v30 — качество тем проверяется **после ответа LLM**, а не только промптом.

- каждая Mistral-тема проходит локальную проверку соответствия научным областям и истории преподавателя;
- `research_taxonomy.py` теперь используется и для AI-генерации, а не только для «Демо без ИИ»;
- для преподавателей с несколькими научными областями сервер требует покрытие разных областей в одном наборе;
- повторяющаяся методологическая подпись (например, многоагентные системы) извлекается из истории и передаётся в prompt;
- семантические дубли проверяются локальной multilingual embedding-моделью через FastEmbed/ONNX, независимо от Mistral API;
- если локальная embedding-модель временно недоступна, используется отдельный lexical-only режим с собственными порогами `25/50` вместо embedding-порогов `45/70`;
- проверка выполняется относительно прошлых тем, уже утверждённых тем и тем текущего batch, поэтому ловятся и перефразированные исторические дубли, и внутрибатчевые повторы;
- перед XLSX/Google Sheets выполняется обязательный полный локальный recheck;
- в UI появилась оценка «Соответствие профилю» и покрытые научные области;
- в XLSX/Google Sheets добавлены колонки профиля, метода similarity и provenance модели;
- по умолчанию batch не смешивает `ministral-8b-2512` и `ministral-3b-2512`; fallback на 3B — только opt-in через `MISTRAL_ALLOW_SMALL_FALLBACK=true`;
- backend regression suite: `61 passed`.

### Локальные embeddings

По умолчанию:

```env
LOCAL_EMBEDDING_ENABLED=true
LOCAL_EMBEDDING_MODEL=sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2
LOCAL_EMBEDDING_CACHE_DIR=/models/fastembed
```

При первом реальном similarity-запросе FastEmbed скачает модель; Docker volume `vkr_models` сохраняет её между перезапусками. Если загрузка/ONNX недоступны, приложение продолжит работать в честно помеченном `local-lexical` режиме.

## V31: если structured generation таймаутится

V31 использует компактный batch-prompt и короткие rationale. Для 5 тем модель сначала генерирует 7 кандидатов с output budget около 1100 токенов, после чего локальный Quality Gate отбрасывает дубли и профильные промахи. `ministral-8b-2512` получает до 40 секунд на один запрос; скрытого local fallback нет.

## V32 — Balanced Quality Gate

V32 исправляет регрессию `4/5`: Quality Gate больше не ломает весь AI-batch из-за одной пограничной темы. Точные/почти точные дубли и технически плохие названия по-прежнему блокируются, а спорные по профилю или похожести Mistral-кандидаты идут в AI-reserve. После двух repair-запросов лучший reserve-кандидат может заполнить недостающее место с явным предупреждением в интерфейсе. Локальный банк в AI-режиме не используется. Backend regression suite: `62 passed`.
