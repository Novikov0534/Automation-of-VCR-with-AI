# Архитектура VKR AI v23

## Основные сущности

- `Teacher` — постоянный справочник преподавателей.
- `PastTopic` — историческая одобренная тема преподавателя с происхождением из XLSX.
- `GenerationBatch` — один независимый запуск генерации.
- `GeneratedTopic` — новая тема с локальным и глобальным показателями похожести.
- `AppSettings` — настройки Mistral, Google Sheets и генерации.
- `QualityEvaluationRun` / `SimilarityCalibrationPair` — экспериментальные backend-сущности исследовательской части; основной UI от них не зависит.

## Генерация

1. Пользователь выбирает преподавателей и количество тем.
2. Backend формирует адаптивные пакеты: не более 5 преподавателей и примерно 40 тем на один запрос.
3. В Mistral отправляются `teacher_id`, научные области, прошлые одобренные ВКР, текущие утверждённые темы, фокус генерации и список тем, которые нельзя повторять.
4. `POST /v1/chat/completions` возвращает structured JSON по схеме `teachers[] → teacher_id + topics[]`.
5. Backend валидирует конкретность формулировок и отбрасывает дословные/слишком близкие повторы.
6. Если тем не хватило, выполняется одна групповая repair-попытка только для преподавателей с дефицитом.
7. Прошлые темы и локальный демонстрационный банк не подставляются вместо ответа AI.

Все вызовы Mistral в процессе приложения проходят через одну очередь. Новый HTTP-запрос начинается не раньше чем через 1,25 секунды после предыдущего, а `429/5xx` повторяется с паузами `2 → 4 → 8` секунд. Это исключает параллельные вызовы chat, embeddings и проверки моделей в пределах backend-процесса.

## Similarity

- **Локальный показатель** сравнивает новую тему только с `PastTopic` данного преподавателя.
- **Глобальный показатель** сравнивает её с историческими `PastTopic` всех преподавателей и другими темами текущего `GenerationBatch`.
- Точное нормализованное совпадение определяется отдельно как дубликат.
- При доступном `mistral-embed` используется гибрид содержательной лексики и embedding-сигнала.
- Если embeddings временно недоступны, расчёт автоматически переходит в lexical-only режим; генерация тем при этом не блокируется.

## Интеграции

Обычное чтение статуса не отправляет запрос в Mistral и поэтому не расходует бесплатный RPS. Полная проверка подключения выполняется только явно по кнопке пользователя:

- `unconfigured` — ключ/данные отсутствуют;
- `error` — внешний сервис отклонил ключ или запрос;
- `connected` — ключ настроен; явная полная проверка дополнительно подтверждает доступ к API.

Полный тест Mistral последовательно проверяет список моделей, выполняет небольшую реальную structured-генерацию и один пакетный запрос embeddings. Ошибка embeddings не блокирует сохранение рабочего ключа генерации.

Google Sheets проверяется через сервисный аккаунт. При указанном spreadsheet ID дополнительно проверяется право редактирования конкретной таблицы.

## Удаление и история

- удаление преподавателя требует подтверждения;
- удаление исторической темы можно отменить в коротком окне;
- удаление `GenerationBatch` удаляет его связи и сгенерированные темы;
- полная очистка истории сохраняет `Teacher` и `PastTopic`, а нумерацию наборов сбрасывает к `#1`.
